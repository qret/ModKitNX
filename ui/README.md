# ui/ — экраны ModKitNX (Borealis) и что нужно сборке

Суть приложения: оно изменяет игру, рассчитанную на прошивку новее, чтобы она запустилась на вашей (README). Правила
UI: просто и последовательно; выбор — сразу под тем, к чему относится. `.nro` собирается CMake (`Guides/en/06-building.md`).

| Игра | `ui/src/game_activity.cpp`, `game_activity.xml` | «Что есть» (версия, обновление, требуемая прошивка, как прочитан код, ZBIC — снимать или нет по правилу ядра, наш модуль); «sdk» (что требует игра: NCA и своя sdk; что сейчас у игры; прошивка и Atmosphère; вывод словами; выбор sdk прямо под вопросом, у sdk, взятой из игры, — подпись «из игры …»; «Подменить sdk» — только когда одной подмены достаточно, наша подмена стоит — красная «Удалить подмену»; «Подробности»; подмена нужна, а подходящей sdk нет — «Найти sdk в других играх»); «Что исправит модуль» (прогноз ядра `mk::forecast_fixes` для импортов игры × выбранной для подмены или текущей sdk: подкарточками — см. «Стиль» ниже: исправит / не вмешивается / не восполнит / совет; игре не нужно — серой строкой; технические имена и правило Vulkan — «Технические подробности»; меняется вместе с выбором sdk; «не восполнит» (`mk::sdk_gaps`) — только для sdk, выбранной для подмены, имена читаемые (`source/symbol_names.hpp`), «Подробности» — полный список с именами .dynsym; функции онлайн-служб (`onlineServiceOf`: друзья, аккаунт в сети…) — нейтральной подкарточкой «Функции онлайн-сервисов», жёлтая и «Совет» — только для остальных); «Моды» (выбор под вопросом; по умолчанию — мод из квитанции); «Сейчас стоит: обычная / отладочная сборка» (по квитанции) и флажок «Отладочная сборка» — включён, если стоит отладочная. Кнопки решает одна чистая функция `mk::app::decideGameActions` (`source/game_actions.hpp`, хост-тест `tests/host/game_actions_tests.cpp`) и перестраивает выбор sdk, мода и флажка: не установлено — «Установить» (подмена выбранной sdk входит в неё — строка «Установка также подменит sdk на …»; кроме подмены делать нечего, но есть пробелы, которые модуль не восполнит, и флажок отладки снят — «Установить» = план «Подменить sdk», строка «… — больше ничего не нужно»); установлено — красная «Удалить установленное» и «Переустановить» только с причиной под ней (устарело, вид сборки не совпал с флажком — `debug/will_plain`, `debug/will_debug`, другой мод, другая sdk); игре ничего не нужно (`gameNeedsNothing`: sdk игры не новее прошивки, ZBIC не снимается, модулю нечего исправлять и восполнять) и модуль с подменой не стоят — без модов выбора sdk, флажка отладки и «Установить» нет, вместо них зелёная подкарточка «Игре ничего не нужно» (`nothingNeeded`), с модом — «Установить мод» (модуль и мод без подмены sdk, `installModOnly`; мод не выбран — строка «Сначала выберите мод выше»), флажок отладки есть, выбора sdk нет; есть отчёт этой игры — подкарточка «Отладка» (время последнего отчёта, «Отчёт отладки»); есть отчёт модуля или отчёт Atmosphère о падении — «Собрать логи для отправки» (поиск — `findReports`, в фоне) |
| Операция | `ui/src/operation_activity.cpp`, `operation_activity.xml` | один экран: план «Будет сделано» / «Будет удалено» → кнопка (для удаления — ещё диалог подтверждения) → прогресс (B заблокирована) → итог; «Готово» — назад, экран игры перечитывается; пока на экране нечего выбирать («Составляю план…», запись) — фокус на теле экрана без рамки, B работает; кнопка удаления — красная (`dangerStyle`) |

| Нет ключей | `ui/src/no_keys_activity.cpp`, `no_keys_activity.xml` | крупные нумерованные шаги Lockpick_RCM (текст спецификации) |

Старый корневой отчёт — только если он от этой игры. Кнопка на странице игры — если отчёт этой игры есть (`findReports(tid)`). Выбирать нечего — кнопка «Назад» с фокусом (без пустой рамки) |

| Длинный текст | `ui/src/text_sheet.cpp`, `ui/include/ui/text_sheet.hpp` | один общий экран для всего, что может не поместиться в окно (`openTextSheet`): шапка с заголовком; прокручиваемая колонка — крупная строка, серая строка-пояснение, блоки-подкарточки (`SheetBlock`: заголовок, строки-абзацы, тон, значок), серое примечание; ряд кнопок закреплён внизу (по умолчанию «Закрыть», фокус на кнопке; кнопка закрывает экран и потом выполняет своё). Текст не фокусируется: вверх/вниз крестовиной и левым стиком — прокрутка шагом, L/R — на страницу, правый стик — плавно, касание; влево/вправо — между кнопками; B — назад. Строки переносятся по ширине, слово длиннее строки (имя функции, путь) — посимвольно. Где: окно обновления, «Технические подробности», «Не восполнит» → «Подробности», «sdk» → «Подробности», «Найти sdk» → «Подробности», текст отчёта отладки |

Есть новее — экран длинного текста «Доступна версия X.Y.Z»: «У вас версия …», «Что нового» целиком с прокруткой, внизу «Обновить» (в фокусе) / «Не сейчас» / «Пропустить эту версию» → загрузка с полосой и проверка файла → «Перезапустить»; замена `.nro` — при выходе (логика и сеть — `platform/app_update`). «Проверить обновления» в настройках отвечает всегда и снова предлагает пропущенную версию |

Языки: `en-US` (основной и запасной: ключа нет в языке — берётся отсюда), `ru`, `uk`. Строки — `resources/i18n/<код>/`
`app.json` (экраны), `core.json` (план, предупреждения, итог и ошибки ядра), `hints.json` (подсказки кнопок borealis),
`update.json`, `theme.json`, `sdkscan.json` (обновление, тема, поиск sdk; ключи `<файл>/<ключ>`, `trk`);
список языков — одно место, `resources/i18n/languages.json`; как переводить — `TRANSLATING.md`, проверка —
`tools/i18n_check.py`. Ищет строки `ui/i18n` (`tr`, `trf`, `trText`), а не `brls::getStr`: язык меняется на ходу
после экрана первого запуска; borealis получает тот же язык до `Application::init` (подсказки кнопок). Тексты в XML —
через `id="tr/<ключ>"` (`translateIds`), не `@i18n/…`. Ядро отдаёт строки ключом + параметрами (`mk::Msg`,
`mk::Texts::msg`, `mk::Error::msg`), русский текст ядра — запасной (журнал, хост-тесты, сверка с эталоном).

## Стиль: карточки и подкарточки

Экран — колонка карточек (`makeCard`: скруглённая панель, заголовок `makeSectionTitle`). Таблица «ключ — значение»
(`makeInfoLine`) остаётся таблицей. Вердикт, предупреждения, совет и итог не смешиваются с таблицей и техникой —
каждая смысловая группа идёт **подкарточкой** (`ui/common.hpp`: `makeSubCard(Tone, значок, заголовок[, размер])`,
строки — `addSubLine`, кнопка или другой вид — `addSubView`, с отступом под текст заголовка):

| Тон | Когда | Значок (`icon::`) |
|---|---|---|
| `Tone::Ok` | сделано, исправит, работает | `kOk` (галочка в круге) |
| `Tone::Warn` | требует внимания, не восполнит, проблемы | `kWarn` (треугольник) |
| `Tone::Bad` | ошибка, сделать нельзя | `kBad` (крестик в круге) |
| `Tone::Info` | что дальше, совет (`kTip` — лампочка) | `kInfo` |
| `Tone::Neutral` | справка без оценки | `kInfo` |

Цвета — только через тему: фон `mk/<тон>_bg`, значок и заголовок `mk/<тон>_text` (в тёмной теме светлее основного
цвета, в светлой — темнее; регистрируются в `applyThemeAtStartup` для обеих тем). Заголовок может быть целой фразой
(вердикт) — тогда размер меньше (18–21). Значки — шрифт Material Icons borealis (`romfs:/material`, запасной шрифт
текста): в нашем `font.ttf` знаков ✓ ⚠ ● нет, а коды `E000–E1FF` заняты значками кнопок Switch, поэтому коды —
из диапазона выше (`E86C`, `E8B2`, `E5C9`, `E88E`, `E90F`). Технические строки (символы, импорт, решение ядра) —
на экран длинного текста (openTextSheet, «Подробности»), не в основной вид. Длинный или переменный текст (списки, пути, описание выпуска, текст отчёта) — только туда, не в rls::Dialog: диалог borealis не прокручивается, и когда перенесённый текст выше экрана, Label отказывается от переноса и рисует его одной строкой за краями окна. Диалог — только для коротких вопросов и уведомлений, через makeShortDialog (текст в колонке на всю ширину окна, с переносом). Кнопки внутри подкарточки фокусируются и прокручиваются как обычные
(высота 48, `addSubView`). Удаляющие кнопки («Удалить установленное», «Удалить подмену», «Удалить» на экране
операции) — красные: свой стиль `dangerStyle()` (ключи темы `mk/danger_bg`, `mk/danger_text`; в borealis красного
стиля нет), рамка фокуса — как у основной кнопки.

Где применено: страница игры — «Что исправит модуль» (заголовок с версией sdk; зелёная «Исправит — N из M», серая
или жёлтая «Модуль не вмешивается», жёлтая «Не восполнит» с «Подробностями», синяя «Совет»; «Игре не нужны» — серой
строкой; символы и правило Vulkan — «Технические подробности»), «Что есть» (таблица + жёлтая «Требует внимания»
с кнопкой «Что делать?»), «sdk» (вывод — подкарточкой по тону, в ней же «Найти sdk в других играх»), «Моды» (нет
модов — серая); экран операции (сделать нельзя — красная; предупреждения плана, пояснение удаления, отладочная
сборка; итог: ошибка, «Сделано», «Проблемы», что дальше); «Отчёт отладки» (вывод по каждому отчёту, нет отчётов,
старый отчёт); «Логи для отправки» (куда прислать — синяя, чего нет — жёлтая, сбой — красная); окно обновления
(«Что нового», ставить некуда). Не применено: настройки (паспорт консоли и папки — таблицы), список игр (значки
строки), «Найти sdk в других играх» (экран уже один вопрос с выбором и короткий итог), первый запуск, апплет.

## Что нужно от сборки

1. **Пути заголовков:** `ui/include`, `core/include`, `platform/include`, `source`, заголовок nlohmann/json
   (`cmake/ModkitDeps.cmake`; всё есть в `CMakeLists.txt`). Для обновления — libcurl из portlibs devkitPro (`switch-curl`).
2. **Определения:** `APP_NAME`, `APP_VERSION` (уже передаются) — `platform/paths.hpp` берёт имя и версию из них.
   `BRLS_RESOURCES="romfs:/"` — уже.
3. **`userAppInit`:** свой не определяется — нужен штатный `switch_wrapper.c` borealis (`MODKIT_OWN_APPINIT=OFF`, как сейчас).
   Он поднимает romfs, pl, set, set:sys, psm, nifm, lbl и сокеты; ns и ncm приложение поднимает само
   (`platform/services`), spl — по месту.
4. **Шрифт:** ~~системный `PlSharedFontType_Standard`, кириллица есть~~ — кириллицы в нём нет (проверено на
   консоли). Шрифт — свой `resources/font/font.ttf` (Noto Sans, OFL) → `romfs:/font/font.ttf`: штатный `SwitchFontLoader`
   borealis берёт его основным шрифтом всего текста; японский Standard добавлен ему запасным (`source/main.cpp`,
   `addStandardFontFallback`) для названий игр. Патчи borealis не нужны.
5. **romfs:** `resources/` целиком (xml, i18n, `img/cover_blank.png`) + i18n/img/sys/material borealis — как в
   `CMakeLists.txt`. Иконка — `resources/icon.jpg` (из TorrentShopNX, см. `resources/CREDITS.md`).
6. **Модули:** `romfs/modules/manifest.json` (schema 3). Мост выбирает вариант по свойствам описи: обычный —
   `autofix && !diag && !early && !gfx`; для мода со своим модулем — то же с `early`; «Отладочная сборка» —
   `autofix && diag` (+ `early` для мода с модулем). Нет отладочного варианта — ставится обычный с предупреждением.
   Свойства выбранного варианта (`diag`, `gfx`) мост передаёт ядру как `InstallOptions::diag`/`diag_gfx` — они попадают
   в квитанцию (`diag`, `diag_gfx`, `module_variant`), по ней экран игры показывает «Сейчас стоит».
7. **zlib:** нужна только `platform/src/nacp_text.cpp`, а он больше не вызывается (название и сжатую таблицу
   NACP разбирает ядро `mk::parse_nacp`). Файл компилируется глобом `platform/src/*.cpp`; убрать его из сборки или
   перенести в архив — ещё не решено.
8. `-Werror=format` — наши `MK_LOG(...)` проверены `-Wformat` (u64 как `%lX`/`%lu`, `size_t` как `%zu`).
